# Repository Guidelines

## Project Structure & Module Organization
- Sources: `cv.tex` (entry point) and `structure.tex` (layout/macros).
- Assets: `lex.png` (and any added images) in the repo root.
- Output: `cv.pdf` is generated by the build; do not edit by hand.
- Docs: `README.md` (quick intro), `CLAUDE.md` (assistant notes).

## Build, Test, and Development Commands
- `make` / `make all`: Compile PDF with two passes for references.
- `make quick`: Single-pass compile for fast iteration.
- `make clean` / `make distclean`: Remove aux files / also remove `cv.pdf`.
- `make view`: Build and open the PDF using an available viewer.
- `make watch`: Recompile on changes (requires `inotifywait`).
Prerequisite: `pdflatex` available in `PATH` (TeX Live/MacTeX).

## Coding Style & Naming Conventions
- Content lives in `cv.tex`; keep reusable layout/macros in `structure.tex`.
- Prefer provided macros (`\CVSection{}`, `\CVItem{}`, `\aboutme{}`) over ad‑hoc formatting.
- Indent LaTeX environments with two spaces; keep lines ~100 columns for readability.
- Name image/files lowercase with hyphens (e.g., `company-logo.png`).

## Testing Guidelines
- Build must complete with zero LaTeX errors. Example: `make && make view`.
- Manually verify `cv.pdf` for overfull boxes, spacing, and link targets.
- If adding/altering macros, compile twice and confirm no layout regressions.

## Commit & Pull Request Guidelines
- Use clear, scoped messages (prefer Conventional Commits):
  - `feat(cv): add research section`
  - `fix(layout): tighten sidebar spacing`
- PRs should include: purpose, concise summary, manual verification steps, and before/after screenshot when UI changes.
- Link related issues if applicable; keep diffs minimal and focused per PR.

## Security & Configuration Tips
- Do not commit generated artifacts beyond `cv.pdf`; keep images reasonably sized.
- No secrets/config required. Remove personal data you do not intend to publish.
